# Demo 手把手验证设备接口配置

在 React 或 Vue demo 中，把设备列表和设备实时数据配置到同一个连接，然后用本地 HTTP 服务分别测试两项请求。

## 1. 启动本地服务和 demo

在仓库根目录开两个终端。终端一运行：

```bash
pnpm dev:data-source
```

终端二运行 `pnpm dev:demo:react` 或 `pnpm dev:demo:vue`。用浏览器打开终端二打印的 **Local** 地址。以下示例用 `http://127.0.0.1:5173`。

验证代理时，可以在浏览器直接打开 `http://127.0.0.1:5173/local-api/api/devices`，应看到包含 `pump-1` 和 `pump-2` 的 JSON 数组。若页面使用其他端口，用终端实际打印的地址替换。[本地服务的路由和场景表](./local-data-source-testing.md)

## 2. 新建连接

左栏切到 **数据（Data）**，点 **新建连接（New connection）**，填写下表后点 **保存连接（Save connection）**。

| 字段 | 示例值 |
| --- | --- |
| 连接名称（Connection name） | `本地设备` |
| 服务地址（Service URL） | `http://127.0.0.1:5173/local-api` |
| 认证（Authentication） | 无认证（No authentication） |
| 超时（秒） | `5` |

服务地址使用 demo 当前的地址加上 `/local-api`。代理会把请求转发给 `http://127.0.0.1:4310`。

## 3. 保存并测试两个标准接口

在刚保存的连接行中分别使用 **设备列表** 和 **设备实时数据** 两个入口。

| 入口 | 方法 | 请求路径 | 成功时的解析后 JSON |
| --- | --- | --- | --- |
| 设备列表（Device list） | `GET` | `/api/devices` | 两条记录包含 `deviceId` 和 `deviceName` |
| 设备实时数据（Device realtime data） | `GET` | `/api/devices/realtime` | 两条记录包含 `runningStatus`、`runningStatusEnum` 和属性数组 `data` |

1. 打开第一个入口，填好方法和请求路径，保持参数区域为空，点 **保存接口（Save endpoint）**。出现「接口已保存」后点 **关闭请求（Close request）**。
2. 再次打开同一个入口，确认请求路径已恢复，点 **运行请求（Run request）**。测试结果应为「成功」，显示 HTTP 200 和「2 条记录」。
3. 对另一个入口重复以上步骤。实时数据中可以看到两台泵的状态。离线的 `pump-2` 返回当前状态码 `17`、温度历史读数 `24.8` 和开关 `null`。这些业务值均符合响应规范。

## 4. 用请求参数切换测试场景

任选一个已配置的标准接口，保持**请求路径**不变。在 **参数（Parameters）** 中点 **添加参数（Add parameter）**，新增一行：

| 字段 | 值 |
| --- | --- |
| 名称 | `scenario` |
| 类型 | 字符串（String） |
| 位置 | 查询字符串（Query string） |
| 使用默认值 | 勾选 |
| 默认值 | 下表中的场景值 |

点 **运行请求**，观察解析后的请求 URL 和测试结果。更换默认值可以逐一验证。

| `scenario` | 预期结果 |
| --- | --- |
| `empty` | HTTP 200，解析后的 JSON 为 `[]`，显示「成功」和「0 条记录」 |
| `missing-field` | HTTP 200，显示「失败」。设备列表提示 `$[0].deviceName`，实时数据提示 `$[0].data` |
| `http-500` | 显示「失败」，并提示「服务返回 HTTP 500」 |
| `slow` | 超时设为 5 秒时，约 1.5 秒后返回成功。连接超时改为 1 秒时会看到超时提示 |
| `auth-required` | 在「无认证」连接上返回 HTTP 401，供检查认证错误反馈 |

这组实验可直接运行草稿。结束后关闭弹窗并选择放弃更改，再次打开即可用已保存的正常配置继续测试。

## 5. 排查与验收

| 现象 | 检查 |
| --- | --- |
| 连接失败或代理返回错误 | 确认 `http://127.0.0.1:4310/health` 能返回 JSON，服务地址的端口与 demo 当前端口一致 |
| 路径校验失败 | 请求路径中只填写 `/api/devices` 或 `/api/devices/realtime`。场景值填在参数区域 |
| 运行后收到未知路径 404 | 确认连接服务地址以 `/local-api` 结尾，再核对第 3 节的路径和方法 |
| 脚本已改但仍返回旧格式 | 停止已启动的本地测试服务，重新运行 `pnpm dev:data-source` |

- [ ] 同一个连接下可以分别保存两个接口，关闭后重新打开能看到配置。
- [ ] 两个接口正常请求都显示「2 条记录」。
- [ ] 空数组、缺少必填字段和 HTTP 500 有各自的反馈。
