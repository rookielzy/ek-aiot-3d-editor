> **约定**：`代码字体` 里的文字都是界面上真实出现的按钮名/字段名/状态词。默认中文界面；英文界面的对照见附录 B，想切界面语言见 §1 末尾。

## 0. 先建立三张心理地图

动手前只需要记住三件事，后面每一步都会指向它们。

### 地图 A：界面分区

```
┌──────────┬───────────────────────────────────────────────────────────┐
│ 导航竖条 │ 顶部工具栏（Project 菜单 · 变换工具 · 语言切换）           │
│ 场景 N   ├───────────────────────────────────────────────────────────┤
│ 资源 N   │  3D 视口                                     ┌──────────┐ │
│ 数据 N   │  ┌──────────────────────────────────────────┐ │ 设备详情卡│ │
│ 项目 N   │  │ 数据预览：启动数据预览 / 刷新数据 / 状态   │ └──────────┘ │
│          │  └──────────────────────────────────────────┘               │
│ ┌──────┐ ├────────────────────────┬──────────────────────────────────┤
│ │左栏  │ │ 左栏「项目面板」        │ 右栏「检查器面板」                │
│ │项目面板│ │ （随导航按钮切换）      │ 属性 / 环境 / 场景               │
│ └──────┘ │                        │                                  │
└──────────┴────────────────────────┴──────────────────────────────────┘
```

- 最左边那一**竖条图标按钮**是导航：`场景`、`资源`、`数据`、`项目`，各自带一个数字（层级节点数 / 资源数 / 数据配置数 / 问题数）。
- 点一下导航按钮 = 把左栏切到那个面板；**再点一次同一个按钮 = 收起/展开左栏**——这是最容易让人以为「按钮没反应」的地方。
- 右栏是检查器，默认停在 `属性` 分组。

### 地图 B：数据功能的四块界面

| 界面 | 在哪里 | 干什么 |
| --- | --- | --- |
| **数据源面板** | 左栏，点导航 `数据` | 建/改/删连接，建查询，管理查询的绑定 |
| **请求测试** | 在某个连接行上点 `测试请求`，在左栏内联展开 | 不保存任何东西，直接发一次真实请求看结果 |
| **查询配置** | 点 `新建查询` / 查询行的 `编辑` 打开的弹窗 | 方法、路径、参数、刷新策略 + 字段映射 + 映射预览 |
| **设备数据（绑定）** | 右栏 `属性` 分组最底部，在变换与材质之下 | 选中一个 3D 对象，把查询的某个设备绑到它身上 |

外加两块**只在特定条件出现**的东西：

- **数据预览浮层**：视口内、工具栏下方偏上，含 `启动数据预览` / `刷新数据` 两个按钮和一行状态。**在保存第一个绑定之前它完全不渲染**，所以现在看不到是正常的。
- **设备详情卡**：视口右下角。**只在「预览已开启 + 选中了一个已启用绑定的对象」时出现**。

### 地图 C：数据流向（出问题时用来定位）

```
连接（服务地址 / 请求头 / 超时）
  └─ 查询（方法 + 路径 + 参数 + 刷新间隔/过期时限 + 业务成功条件
        + 映射：数据根路径 → 设备 ID 路径 → 属性列表 → 采样时间 → 源质量）
        └─ 对象绑定（选查询 + 设备 ID + 详情字段 + 字段精度 + 状态颜色规则）
              └─ 数据预览（启动/刷新/停止）→ 共享请求 → 详情卡 / 对象颜色
```

**排错口诀**：先在「请求测试」里确认**连接**能通；再在「映射预览」里确认**映射**对；最后才去碰**绑定**和**预览**。三层任何一层没确认就往下走，都会在上层呈现成一个含糊的错误。

看到这两行就算成功：

## 2. 第一步：建连接

1. 左侧导航点 `数据`。左栏出现「数据源」面板，标题右侧显示 `0/0`，有 `新建连接` 按钮、一个 `搜索连接` 输入框、下面是一个空的连接列表，再下面是 `查询` 小节。
2. 点 `新建连接`。表单在左栏内展开，字段依次是：`连接名称`、`服务地址`、`认证方式`、`公共请求头`、`超时（秒）`，底部是 `保存连接` / `取消`。
3. 填写：

| 字段 | 填什么 | 说明 |
| --- | --- | --- |
| `连接名称` | `本地设备` | 任意；重名会被拒绝 |
| `服务地址` | `http://localhost:5173/local-api` | **端口必须和终端 2 打印的端口一致** |
| `认证方式` | `无认证` | demo 没接凭证库，选 Bearer/API Key 会提示「宿主未提供凭证」，见 §7 |
| `超时（秒）` | `3` | 默认 10 秒；设小一点能让 §6 的慢响应实验更直观 |
| `公共请求头` | 留空 | 可选，随每次请求发送的非秘密头 |

4. 点 `保存连接`。

**应该看到**：
- 表单收起，列表里出现一行 `本地设备`，行内标签有 `无认证`、`3 秒`、`未使用`；
- 面板顶部状态条提示「已保存连接，可撤销。」；
- 左栏标题右侧的计数从 `0/0` 变成 `1/1`——`数据` 导航按钮上的数字同样 +1。

**踩坑点**：
- 地址必须以 `http://` 或 `https://` 开头、**不能带查询字符串或 `#` 片段**，否则保存时报「请使用完整的 HTTP 或 HTTPS 地址。」或「请移除服务地址中的查询字符串和片段。」；
- 不要在 `公共请求头` 里写 `Authorization`、`Cookie`、`Proxy-Authorization`、`Set-Cookie`——这些是保留给认证的，会报「认证请求头不能作为公共或查询请求头。」。

## 3. 第二步：用「测试请求」确认连接真的通

这一步不保存任何配置，纯粹验证「地址 + 头 + 超时」是否正确。

1. 在连接行 `本地设备` 上点 `测试请求`（按钮提示文字是「测试 `本地设备` 的请求」）。左栏展开「测试请求 · 本地设备」，原来的连接列表/查询列表暂时不可点。
2. 顶部有一句说明：「此请求是窗口草稿。响应仅保留在当前会话中，不会保存到项目。」——放心随便试。
3. 填 `请求路径`：`/api/devices`（相对路径，placeholder 是 `/devices/{deviceId}`）。
4. `方法` 保持 `GET`。
5. 看下面 `解析后的请求` 一行，应该显示 `GET http://localhost:5173/local-api/api/devices`。**这是在你真正发请求前就校准地址的最快方式**。
6. 点 `运行请求`。

**应该看到**——`请求结果` 区域（`data-status="success"`）：

| 项 | 期望值 |
| --- | --- |
| 状态 | `200`，并显示耗时如 `18 毫秒` |
| 内容类型 | `application/json; charset=utf-8` |
| 解析后的 JSON | `{"items":[{...pump-1...},{...pump-2...}]}` |
| 原始响应 | 与上面相同的一行 JSON 文本 |

同时在 `解析后的 JSON` 里确认：两条记录、`deviceCode` 分别是 `pump-1` / `pump-2`，并且带 `observedAt` 字段。**这三个字段名稍后要原样填进映射里。**

**出错时对照**：

| 请求结果里的提示 | 含义 | 怎么办 |
| --- | --- | --- |
| `服务返回 HTTP 404。` | 地址或路径拼错了 | 检查 `服务地址` 是否以 `/local-api` 结尾、`请求路径` 是否以 `/api/devices` 开头 |
| `请求失败：Failed to fetch` | 假后端没起 / 端口不对 | 回终端 1 看是否还在运行 |
| `请求超时。` | 超时设太小（比如填了 0.1） | 把连接的超时调到 3 秒以上 |
| `服务以 HTTP 401 拒绝凭证。` | 路径里带了 `?scenario=auth-required` 而请求没带 `x-api-key` | 见 §7 的场景实验，正常路径不该出现 |

看完点测试器里的关闭按钮（或连接行的 `测试请求` 收起它）即可，这一步不会留下任何配置。

## 4. 第三步：建查询并做字段映射

### 4.1 打开查询编辑器

在数据源面板的连接行下面，点 `新建查询`（提示文字「为 `本地设备` 新建查询」）。弹出标题为 `查询配置` 的对话框，里面从上到下是 **请求**、**字段映射**、**映射预览** 三段，底部是 `保存查询` / `取消`。

### 4.2 「请求」段

| 字段 | 填什么 |
| --- | --- |
| `查询名称` | `设备列表` |
| `方法` | `GET`（保持默认） |
| `请求路径` | `/api/devices` |
| `刷新间隔（秒）` | `5`（默认 5） |
| `过期时限（秒）` | `30` |

说明：
- `刷新间隔` 只对 GET 出现；POST 查询是「只读 POST · 手动刷新」，没有自动轮询。
- `过期时限` 不能小于 `刷新间隔`，否则保存会报策略无效。
- **先别点 `运行请求`**（如果你点了也没关系，它就在这一段里，跑出来的响应会同时填进 `映射预览` 的示例 JSON，正好省事）。本引导走「先离线映射、再联网验证」的顺序，更不容易被网络问题干扰。

### 4.3 「字段映射」段

这是整条链路**最容易填错**的地方，一次填一项，每填完看一次右侧预览。

1. `数据结构`：选 `设备数组`（默认）。响应里是 `items: [...]`，属于数组。
2. `数据根路径`：填 `items`。
   - 含义：设备数组在 JSON 的哪个位置。留空 = 整个正文就是数组。
   - 这里填错（比如填 `data` 或 `items[0]`）会得到「配置的数据根不存在。」或数据根结构不符。
3. `身份来源`：选 `字段路径`（默认），然后 `设备 ID 路径` 填 `deviceCode`。
   - 这是「哪条记录属于哪台设备」的唯一依据，必须和响应对得上。
4. `显示名称路径`：填 `name`（可选，填了详情卡副标题会显示 `Pump 1 · pump-1`）。
5. `属性`：点 `添加属性` 三次，逐行填（行内字段名带序号，例如「属性 1 键」「属性 1 源路径」）：

| 属性 # | 键 | 显示名 | 类型 | 源路径 | 单位 |
| --- | --- | --- | --- | --- | --- |
| 1 | `temperature` | `温度` | 数字 | `temperature` | `℃` |
| 2 | `running` | `运行` | 布尔 | `running` | （空） |
| 3 | `name` | `名称` | 字符串 | `name` | （空） |

   - `键` 是绑定和颜色规则里引用属性用的稳定名字，建议用英文无空格；`显示名` 是详情卡上看到的文字。
   - `转换` 保持 `原值`。想试「乘系数加偏移」就选它，会多出 `系数` / `偏移` 两个输入框。
6. `采样时间`：`采样时间路径` 填 `observedAt`，`采样时间格式` 保持 `带时区的 ISO 8601`。
   - 不填也能跑，只是详情卡的「采样」会显示「未知」。**填了才能看到详情卡上「采样」和「接收」是两个时间。**
7. `源质量`：可以留空。留空时所有属性质量显示「未知」——这是设计行为（HTTP 200 不代表设备数据可信），不是 bug。

### 4.4 用「示例 JSON」离线验证映射（不发网络请求）

滚到最下面的 `映射预览` 段：

1. 把下面这段粘进 `示例 JSON` 文本框：

```json
{
  "items": [
    { "deviceCode": "pump-1", "name": "Pump 1", "temperature": 26.4, "running": true,  "observedAt": "2026-11-09T10:00:00.000Z" },
    { "deviceCode": "pump-2", "name": "Pump 2", "temperature": 24.8, "running": false, "observedAt": "2026-11-09T10:00:05.000Z" }
  ]
}
```

2. 点 `应用示例 JSON`。
3. **应该看到** `已映射设备` 下面出现两个块：
   - `设备 pump-1`（副标题 `Pump 1`）：`采样时间` / `接收时间` / `源质量：未知`；
   - 下面一张表 `属性结果 pump-1`，列是 `属性 | 原值 | 映射值 | 状态 | 问题`，三行都是 `正常`；
   - 同样一份 `设备 pump-2`。
4. 段顶部会出现一条提示：「正在预览示例 JSON」（使用了真实响应则是「已用真实响应测试」）。如果你在应用样本之后又改了映射，会出现「草稿在此样本之后已变化」——重新点一次 `应用示例 JSON` 即可。

**常见映射错误的定位方法**（错误会出现在 `映射问题` / `映射错误` 里）：

| 提示 | 原因 | 修法 |
| --- | --- | --- |
| 配置的数据根不存在。 | `数据根路径` 写错 | 对着响应顶层键核对，`items` 不要写成 `data.items` |
| 数据根结构不符 | 期望数组却拿到对象（或反之） | 检查 `数据结构` 是 `设备数组` 还是 `单对象` |
| 设备 ID 字段缺失 | `设备 ID 路径` 指向的字段在记录里不存在 | 改成 `deviceCode` |
| 设备 ID 重复 | 两条记录身份值相同 | 换一个唯一字段 |
| 属性 `xxx` 源字段缺失。 | 某个属性的 `源路径` 打错 | 对照响应里的键名 |
| 属性状态为 `无效` | 类型对不上（如用 `数字` 类型映射 `"26.4"` 以外的字符串） | 改 `类型` 或改用 `严格数值` 转换 |

### 4.5 保存查询

点 `保存查询`。

**应该看到**：
- 对话框关闭，数据源面板的 `查询` 小节出现一行 `设备列表`；
- 行摘要显示 `3 个属性 · 设备数组`；若之前没跑过真实请求，行内还会标 `尚未测试`（这是允许的，无响应也能保存合法配置）；
- 面板提示「查询已保存，可撤销。」。

## 5. 第四步：绑定到 3D 对象

### 5.1 选中对象

在视口里点那辆车，或者点导航 `场景` 切到场景面板、在层级树里点 `Toy Car`。右栏检查器顶部会显示选中的对象名和节点数量。

> Toy Car 是一个导入的 GLB 节点，场景打开时层级里它下面还会展开子节点。**直接点父节点 `Toy Car` 最稳**——点到子节点时「设备数据」区块会提示「导入节点不能直接绑定。请改为绑定其所属对象。」并给一个「选择所属对象 Toy Car」按钮，点它一样能到位；点灯光/相机会提示「灯光不能承载设备数据。」

### 5.2 找到「设备数据」区块

确认右栏停在 `属性` 分组（`属性 / 环境 / 场景` 三个 tab 的第一个），然后**一直往下滚**：顺序是 Transform → Material → **设备数据**（英文 `Device data`）。

绑定表单就在这里面，从上到下是：`查询`、`设备 ID`、`绑定参数`、`详情字段`、`状态颜色`、`启用`，底部是 `创建绑定` / `取消`。

### 5.3 填绑定表单

1. `查询`：下拉里选 `设备列表 · 本地设备`。
   - 只有一个查询时它会**自动选中**，且 `详情字段` 会**自动预填该查询的全部属性**——这时你已经可以直接保存了。
2. `设备 ID`：填 `pump-1`。
   - 手打即可。也可点旁边的 `加载设备`：**注意此时结果还是空的**（预览没启动），所以会提示「当前结果中没有设备。可输入 ID 并等待数据。」——这是正常的，不是错误。

## 6. 第五步：启动预览并驱动数据

### 6.1 启动

1. 点视口上方的 `启动数据预览`。
2. **应该看到**：

### 6.2 读详情卡

详情卡内容逐项核对：

| 区域 | 期望 |
| --- | --- |
| 眉标 / 标题 | `设备数据` / `Toy Car` |
| 副标题 | `Pump 1 · pump-1`（因为映射了 `显示名称路径`） |

| 底部三项 | `接收` 本次时间、`采样` 来自 `observedAt`（2026-11-09 10:00 UTC 对应你本地时区的显示）、`源质量 未知` |
| 底部按钮 | `立即重试` |

**注意**：详情卡只在「预览开着 + 选中了有启用绑定的对象」时出现。取消选中对象、关闭预览、解除绑定，它都会消失——消失不代表配置丢了。

### 6.3 观察轮询与过期

- 预览开启后，GET 查询会按 `刷新间隔（秒）` **自动轮询**（每次请求完成后才开始计时）。盯着 `上次刷新` 那行，每 5 秒变一次，详情卡的 `接收` 时间同步变化，`采样` 时间也会变（因为假后端每次返回新的 `observedAt`）。
- 想看「过期」：点 `停止数据预览` 再启动前，先把查询的 `过期时限（秒）` 调到 `2`、`刷新间隔` 调到 `10`，保存后重启预览。大约 2 秒后浮层状态会变成 `已过期`，详情卡状态行显示 `已过期` 并附「上次值未在 2 秒内刷新。」
- 想验证「共享请求不重复」：再复制一辆车（见 6.5），浮层里的 `共享请求` 仍然是 1，`对象：2`。

### 6.4 加状态颜色规则

先 `停止数据预览`（预览期间不允许试草稿颜色）。

1. 回到右栏 `设备数据` 区块，勾 `启用状态颜色`。
2. `颜色属性`：选 `运行`（映射到 `running` 的布尔属性）。
3. `颜色规则` 第一行：运算符 `等于`、值 `true`、颜色点色板里的绿色（`#22c55e`）。点 `添加规则` 再加一行：运算符 `等于`、值 `false`、颜色选红色（`#ef4444`）。
4. 点 `在对象上试用草稿`。Toy Car 应该立刻变色（`pump-1` 的 `running` 是 `true` → 绿）。
5. 把 `设备 ID` 改成 `pump-2`，再点一次试用 → 变红（`running` 是 `false`）。
6. 改回 `pump-1`，点 `保存绑定`。

**再次启动预览**后，颜色由预览数据驱动；停止预览、解除绑定、绑定停用或对象无值，都会恢复到作者设置的材质颜色。无规则命中时也是。

> 颜色只作用于 `MeshStandardMaterial` 材质。如果对象材质类型不支持，表单下方会给出材质能力提示，且不会影响数据本身。

### 6.5 加第二个对象，验证共享请求

## 7. 六种故障态：每种都能在界面上复现

做法统一：**把查询的 `请求路径` 改成带场景参数的路径**，例如 `/api/devices?scenario=empty`，保存后重启预览，然后观察「预览浮层状态 + 详情卡」。实验做完改回 `/api/devices`。

| # | 路径 | 预期浮层状态 | 预期详情卡 | 一句话解释 |
| --- | --- | --- | --- | --- |
| 1 | `/api/devices?scenario=empty` | `没有数据` | 状态 `当前结果没有数据`，字段空 | 响应是 `{"items":[]}`，映射成功但零设备 |
| 2 | `/api/devices?scenario=missing-field` | `部分字段缺失` | 状态 `部分字段不可用`，`温度`、`运行`、`名称` 三行仍显示 `—` | 记录只有 `deviceCode`，其余字段不存在 |
| 3 | `/api/devices?scenario=slow` | 先 `正在加载设备数据…`，约 1.5 秒后 `就绪` | 正常 | 服务端故意延迟 1500ms；连接超时要 >1.5 秒 |
| 4 | `/api/devices?scenario=http-500` | `错误` | 状态 `查询失败` + 「请修复绑定或查询后重试。」 | GET 的 5xx 会按退避重试；停掉预览或改回路径才能恢复 |
| 5 | `/api/devices?scenario=auth-required` | `认证暂停` | 状态 `认证暂停` + 「服务返回 HTTP 401。请修复凭证后重试。」 | 401/403 被判定为凭证问题，**暂停轮询而不是疯狂重试** |
| 6 | POST `/api/query?scenario=business-error` | `错误` | `查询失败` | 需要把查询改成 POST + 勾只读确认 + 路径 `/api/query` + 业务成功条件 `code 等于 0`（见下） |

几个容易踩的点：

- **场景 3**：连接超时是 3 秒、`slow` 是 1.5 秒，所以应当成功；如果把连接超时改成 1 秒，就会变成「请求超时。」并进入退避重试。
- **场景 5**：demo 的请求执行器**不注入任何凭证**，所以「修复凭证」在 demo 里做不了——恢复正常的方式是**把路径里的 `scenario=auth-required` 去掉**，然后点 `立即重试` 或重开预览。这也是理解「认证暂停」这个状态最好的方式：它不会自己恢复，必须有人改配置。
- **场景 6** 的具体做法：
  1. 编辑查询 `设备列表` → `方法` 选 `POST` → 勾上 `我确认此 POST 仅用于读取数据`（不勾就点 `运行请求` 会报「请先确认此 POST 是只读查询，再执行。」）；
  2. `请求路径` 改成 `/api/query?scenario=business-error`；
  3. 在 `业务成功条件` 里 `成功字段路径` 填 `code`、`成功值类型` 选 `数字`、`成功值` 填 `0`；
  4. 点 `运行请求`：服务的 HTTP 状态是 200，但因为 `code: 7 ≠ 0`，请求结果会报「响应未满足业务成功条件。」——**这正是要证明的点：HTTP 成功 ≠ 业务成功**；
  5. 保存后重启预览，浮层显示 `错误`；POST 是手动刷新策略，不会自动轮询，需要点 `刷新数据` 才重发。

> POST 还有一个坑：假后端在任何场景判断之前就会读 JSON body，空 body 直接 400 `{error:"invalid-json"}`。所以 POST 查询必须再带一个参数让它产生 body：`添加参数` → `参数 1 名称` 填 `probe`、`参数 1 默认值` 填 `1`，并把该参数的 `位置` 显式选成 `JSON 请求体`（自动定位时，路径模板里没有的参数会落到 body，显式选更稳）。

## 8. 常见问题（按现象查）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 点了左侧 `数据` 按钮左栏没变化 | 你点的就是当前激活的视图，等于「收起/展开」 | 再点一次 |
| 视口上方找不到 `启动数据预览` | 还没有任何对象绑定（浮层在零绑定且预览关闭时整块不渲染） | 先做 §5 保存第一个绑定 |
| 详情卡不出现 | 预览没开 / 没选中对象 / 绑定的 `启用` 没勾 / 点了卡的 `×` 关掉 | 分别检查；重新选中对象即可复位关闭状态 |
| Transform、Material 改不动 | 数据预览运行期间编辑被锁 | 点 `停止数据预览` |
| `设备数据` 区块显示「选择一个 GLB 对象以配置设备数据。」 | 当前没选中对象（demo 打开时不预选，或选中的是灯光/相机） | 选 `Toy Car`；点到导入子节点时点「选择所属对象 Toy Car」 |
| `保存绑定` 报「请输入设备 ID。」 | `设备 ID` 留空，或只选了候选没提交 | 手打 `pump-1` 或从 `当前结果中的设备` 选一项 |
| `保存绑定` 报「至少选择一个详情字段。」 | `详情字段` 全被移除 | 用 `添加字段` 补回至少一个 |
| `加载设备` 提示「当前结果中没有设备。可输入 ID 并等待数据。」 | 预览未启动，还没有任何结果 | 手打 `pump-1` 先保存绑定，启动预览后再回来用候选 |
| 候选设备列表变了但 `设备 ID` 没变 | 参数签名变了，候选已过期（提示「参数已变化。请重新加载设备。」） | 重新点 `加载设备` |
| 删除查询/连接时按钮是灰的 | 还被对象绑定或其它查询引用 | 先解除绑定；查询提示「请先解除对象绑定，再删除此查询。」，连接提示「连接正在使用中，请先移除其查询。」 |
| `保存连接` 时提示「宿主未提供凭证」 | demo 的执行器不注入凭证，选 Bearer/API Key 用不了 | 选 `无认证`；需要认证的场景用 `?scenario=auth-required` 来观察 401 现象 |
| 所有请求都 404 | `服务地址` 没带 `/local-api`，或 Vite 端口和填的不一致 | 打开 `http://localhost:<端口>/local-api/api/devices` 自检 |
| 所有请求都 `Failed to fetch` | 假后端没起 / 端口被改 | 回终端 1 检查；`DATA_SOURCE_PORT` 改过的话，Vite 代理也要相应改 |
| 看到 `Vite` 的 404 页面而不是 JSON | 假后端没起，Vite 代理把 404 递给了浏览器 | 先起 `pnpm dev:data-source` |
| 映射预览里属性全是「缺失」 | `数据根路径` 少写了一层，或把数组当单对象 | 用 §4.4 的示例 JSON 反复调，直到全部 `正常` |
| 映射预览显示「配置的数据根不存在。」而响应对得上 | 路径写成了 `items.0` 之类 | 用点号和方括号：`items` 或 `data.items`，数组下标写 `items[0]` |
| POST 查询总是 `错误`，响应是 `invalid-json` | POST 没带 body | 补一个 `JSON 请求体` 位置的参数（见 §7 场景 6） |
| 状态是 `已过期` 但后端一直返回 200 | `过期时限` 太短，或响应里的 `observedAt` 太旧 | 把 `过期时限` 调到大于刷新间隔的 2～3 倍；或把 `采样时间路径` 留空只用接收时间 |
| 改完配置界面上什么都没变 | 预览用「配置修订」判断是否要重发 | 点 `刷新数据`，或停/启一次预览 |
