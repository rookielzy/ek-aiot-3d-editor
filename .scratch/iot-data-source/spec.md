# 物联网数据源接口配置实现规格

Status: ready-for-agent

## Problem Statement

组态人员配置查询时需要手动填写响应根路径、设备 ID 路径和属性转换规则。后端可以按已定稿的格式提供设备列表和实时数据，编辑器需要一个能直接配置并测试这两个标准接口的入口。

## Solution

在数据工作区为同一数据源配置设备列表和设备实时数据两项请求。用户可以保存配置、独立测试每个接口，并查看响应是否符合对应的[物联网设备数据源接口规范](../iot-device-api/spec.md)。

## User Stories

1. 作为组态人员，我希望在同一数据源下配置两个接口，以便按用途维护设备列表和实时数据的请求设置。
2. 作为组态人员，我希望两个接口复用数据源的连接地址和认证配置，以便减少重复输入。
3. 作为组态人员，我希望可以分别测试两个接口，以便定位哪项请求或响应需要调整。
4. 作为组态人员，我希望直接校验标准响应，以便完成接口配置时省去字段路径和转换规则的配置。
5. 作为组态人员，我希望看到请求失败、响应格式错误和成功空结果的区别，以便正确判断测试结果。
6. 作为组态人员，我希望保存并重新打开接口配置，以便继续编辑或测试已填写的请求设置。
7. 作为后端开发者，我希望使用业务定义的状态码和离线返回值，以便已有的状态和取数策略符合统一的响应结构。

## Implementation Decisions

- 数据工作区为同一数据源提供设备列表与设备实时数据两项请求配置。请求地址、参数和认证沿用现有连接配置及宿主请求执行边界。每项请求有自己的设置，测试由用户显式触发。
- 测试请求按所选接口类型直接校验标准 JSON 响应。工作台显示测试结果或与该接口相关的错误。合法的空数组表示请求成功且零条记录。表单采用标准接口配置，省去字段映射、值转换和映射预览。
- 响应字段、类型及对应关系以接口规范为准。后端决定状态码、枚举文案和设备离线时实际返回的设备记录、属性及值。校验将这些内容作为数据，检查其是否符合相应的结构和类型。
- 保存项是连接及两项请求的配置。请求测试的响应与诊断作为运行态数据处理。保存合法配置可以先于接口测试。
- core 提供共享的响应校验，工作台沿用现有数据源配置和请求测试入口。

## Testing Decisions

- 在工作台的数据源配置页使用本地 HTTP 夹具验收。使用接口规范里的 JSON 示例作为两项请求的成功响应。在同一数据源下填写并保存两个接口，重新打开配置确认设置，分别点击测试。夹具确认请求命中各自的路径，工作台显示对应的成功结果。
- 在同一请求测试入口确认有效空数组、无效响应和 HTTP 请求失败的反馈。实时数据夹具使用示例中的自定义状态码，并在离线记录中同时返回最后一次读数和 `null`，确认测试接受这些符合结构的业务值。

## Out of Scope

设备选择、对象和属性绑定、运行时数据预览、轮询、详情展示、状态着色以及整个场景的保存和恢复验收，均留到后续重构。旧字段映射的兼容或迁移也不纳入本次范围。

## Further Notes

本地夹具可以在业务后端部署前提供两种标准响应，供工作台验证接入配置。
