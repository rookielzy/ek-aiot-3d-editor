# HTTP 数据源管理交互原型

日期：2026-10-25。问题：连接、查询、字段映射、对象绑定四个环节是否易于理解，用户在异常状态下能否找到下一步操作？

这是用于评审流程的独立原型，尚未代表正式 UI 或已选定的产品决策。代码只位于本目录，未接入 core、React、Vue 或正式示例。

## 打开

直接用浏览器打开同目录的 `index.html`。单文件内含全部 HTML、CSS、JavaScript 与 SVG，无安装、构建、外部字体或 CDN 依赖。

当前会话也提供本机预览地址：`http://127.0.0.1:5193`。本机临时预览服务停止后，可继续直接打开 HTML 文件。

## 建议体验顺序

1. 点击“配置连接”，保留或修改演示服务地址与认证引用，保存并继续。
2. 在查询中分别调整默认区域与本次测试区域，运行模拟查询，检查原始 JSON。
3. 在字段映射中修改数值系数、字段类型或源字段，观察标准数据预览；也可编辑示例 JSON。
4. 保存查询并绑定，为水泵模型 A 选择设备、详情字段和状态颜色。
5. 点击模型 B 或左侧场景对象，为第二个对象复用同一查询，选择另一设备。
6. 开启“数据预览”，点击水泵查看详情，观察共享请求数和对象颜色。
7. 切换“请求失败”“采样时间过期”“字段缺失”“空设备列表”等模拟场景，再恢复正常数据。
8. 使用“引用保护”引导，尝试删除被引用的查询，再解除绑定、删除并撤销。

可通过“载入完整演示”直接获得两个已绑定对象。左侧“状态”或底部“查看状态”展示当前可保存配置、会话状态、模拟请求计数和配置编辑计数。

## 原型边界

- 演示容量为一个连接、一个查询、两个对象；不是完整的多数据源管理实现。
- 支持填写和修改配置，但网络行为全部为内存模拟，不访问填写的服务地址，不接入真实凭证。
- 场景使用可点击的 SVG 空间示意，支持选择、缩放、数据着色与详情卡；不使用正式 Three.js runtime。
- GET 演示手动和定时更新；POST 演示只读确认、JSON body 与手动查询，不模拟设备控制。
- 示例转换覆盖数值乘系数、严格字符串类型以及 1/0 到布尔值。业务成功条件固定为 `code = 0`。
- 数值默认每五秒变化一次。相同查询及区域的两个绑定共用一个模拟请求。
- 配置历史与实时样本分别管理；临时测试区域不会出现在可保存查询配置中。
- 所有数据仅在内存中；刷新即重置。没有 localStorage、真实项目导出或后台持久化。
- 未实现正式需求中的复制连接、跨场景共享、凭证后台、材质槽绑定或批量对象编辑。

## 已进行的浏览器走查

从空白配置完成连接、查询测试、字段映射、对象绑定和数据预览；核对区域 B 的临时测试不改变默认区域 A；修改温度系数后预览即时变化；两个对象共享一个查询；过期时恢复原始颜色；第一台字段缺失不影响第二台；HTTP 503 显示失败；被两个对象引用的查询无法删除，解除引用后可删除。

走查修正了配置窗口底部按钮被内容挤出的问题，并保留表单焦点和滚动位置。原型未新增自动化测试，也未运行正式包测试；正式 runtime 的性能、材质兼容性与项目迁移尚未在此验证。

## 后续评审

待用户体验后确认：配置窗口与对象 Inspector 的分工是否顺畅；映射表是否清楚；详情卡和颜色规则是否足以支撑首期；是否需要缩短首次接入路径。用户尚未选择最终 UI，不向正式代码吸收原型实现。
