# 桌面工作台正式视觉改版规格

Status: ready-for-agent

日期：2026-09-14。
范围状态：用户已认可原型，并于 2026-09-14 确认本规格的测试边界、16 项任务拆分与依赖关系。规格及任务已正式发布为 ready-for-agent。

## Problem Statement

现有工作台的全宽工具栏、面板布局和属性组织，与用户期望的浅色专业 3D 编辑器有差距。用户已经认可运行中的桌面原型，希望将其视觉与空间组织正式落到产品，同时保留既有编辑、资源管理和宿主集成能力。原型只验证主要路径，直接替换正式工作台会遗漏材质槽、资源恢复、重导入、部分导出、双语及扩展区域等能力。

## Solution

以已认可原型的参考密度为默认视觉基准：白色连续面板、浅灰视口、细分隔线、蓝色激活状态；左侧窄导航与内容面板、中央大视口及浮动工具组、右侧属性/环境/场景分组、底部紧凑状态栏与可展开问题详情。

先将 React 工作台及其示例做成完整可验收的桌面编辑体验，再同步 Vue。侧栏可独立收放和调宽，现有操作按职责重新分组。示例提供自带模型、照明和镜头；包本身仍由宿主决定初始场景。

## User Stories

1. 作为桌面编辑者，我希望打开接近已认可原型的白色工作台，以便以中央模型为视觉中心开始编辑。
2. 作为桌面编辑者，我希望在场景、资源、项目之间通过窄导航切换，以便快速找到不同工作内容。
3. 作为桌面编辑者，我希望分别收起和展开左右面板，以便临时扩大视口而不丢失编辑状态。
4. 作为桌面编辑者，我希望用鼠标和键盘调整面板宽度，以便平衡长名称、属性字段和视口空间。
5. 作为桌面编辑者，我希望在不同桌面窗口及问题抽屉展开时保持工具可达，以便不中断编辑流程。
6. 作为场景编辑者，我希望搜索、折叠场景树并选中对象、分组、灯光和导入子节点，以便定位真实编辑目标。
7. 作为场景编辑者，我希望通过视口点选和现有框选能力更新选择，以便让树、属性和状态栏同步。
8. 作为场景编辑者，我希望直接访问移动、旋转、缩放与各自吸附状态，以便精确调整对象。
9. 作为场景编辑者，我希望通过数值输入和坐标轴拖动编辑变换并撤销/重做，以便可恢复地尝试修改。
10. 作为场景编辑者，我希望继续使用复制、粘贴、副本、删除、组合、解组、全选和清除，以便保留已有场景组织效率。
11. 作为场景编辑者，我希望操作网格、地面、坐标轴、边界、悬停、吸附反馈和灯光辅助，以便按任务选择必要视觉信息。
12. 作为场景编辑者，我希望重置、聚焦所选或全部、捕获和应用相机视图，以便快速组织展示视角。
13. 作为属性编辑者，我希望在对象属性、环境和场景分组间切换，以便避免所有字段堆叠在一个长面板中。
14. 作为属性编辑者，我希望在对象级材质和 material-slot 覆盖间选择且随目标正确切换，以便修改准确的材质目标。
15. 作为属性编辑者，我希望继续编辑已有材质字段与纹理槽并看到 unresolved/禁用原因，以便避免误改或误以为修改成功。
16. 作为场景编辑者，我希望编辑照明来源、背景、强度、旋转和现有环境预设，以便保持视觉意图与场景数据一致。
17. 作为场景编辑者，我希望添加、修改和删除现有灯光并编辑阴影相关设置，以便布置场景照明。
18. 作为场景编辑者，我希望捕获、应用、编辑、删除相机视图并设置默认展示视图，以便保存可恢复的构图。
19. 作为资源使用者，我希望批量选择或拖入 GLB、HDR、图片/纹理并指定栅格用途，以便保留完整导入工作流。
20. 作为资源使用者，我希望看到每个文件的导入结果、错误和处理中状态，以便了解部分成功和失败的原因。
21. 作为资源使用者，我希望搜索、按类型和状态过滤、排序资源并查看引用及载荷状态，以便找到需要维护的资产。
22. 作为资源使用者，我希望替换资源和恢复缺失载荷，以便在保留引用的情况下修复项目。
23. 作为资源使用者，我希望重导入 GLB 并看到 remap 结果和 unresolved 诊断，以便安全维护现有导入对象。
24. 作为项目使用者，我希望通过项目菜单打开、完整导出或明确选择部分导出，以便保存工作并看清不完整项目的限制。
25. 作为项目使用者，我希望从导出项目恢复模型、选择、材质、变换和展示视图，以便获得与保存前等价的编辑状态。
26. 作为项目使用者，我希望在状态栏查看项目、资源、保存和运行时摘要，以便了解真实就绪状态。
27. 作为项目使用者，我希望展开问题抽屉查看严重性、来源和可执行恢复入口，以便从发现问题直接进入修复。
28. 作为首次体验者，我希望打开自带可编辑模型、镜头和照明的示例，以便立即看到具有参考图完成度的效果。
29. 作为包使用者，我希望创建空 editor 或传入自己的场景而不被自动加入示例模型，以便自主掌握宿主数据。
30. 作为双语使用者，我希望切换 English/简体中文并保留选择、历史与视口，以便连续完成编辑而不重建运行时。
31. 作为键盘使用者，我希望用可见焦点、控件标签和既有快捷键操作界面，以便可靠使用面板和编辑命令。
32. 作为React 宿主开发者，我希望保留现有 render props、默认工具栏选项和上下文，以便升级视觉而不重写集成。
33. 作为Vue 宿主开发者，我希望得到等价布局和功能并保留 scoped slots 与 locale 事件，以便继续使用既有集成方式。
34. 作为宿主开发者，我希望让折叠、宽度、标签页、抽屉和语言仅作为 UI/session 状态，以便避免污染 durable Scene Snapshot 与项目包。
35. 作为维护者，我希望以固定原型来源及端到端验收判断完成度，以便避免复制原型中的模拟数据和临时实现。

## Implementation Decisions

1. **视觉基线**：以原型提交 a9ebc22 的默认 reference 布局及相关状态截图为验收来源。compact 仅作密度比较，不成为必须上线的模式；实现中可调整字号和间距以容纳完整功能，但不得改变已认可的主要区域关系。用户对效果的认可发生在原型结果文档之后，旧文档“等待视觉评审”的描述不覆盖本次认可。
2. **正式组件范围**：改版作用于 React/Vue EditorWorkbench 默认壳及其内部 UI，不只修改示例 CSS。使用统一语义的设计 token 和控件规则；优先复用现有模块，不为了两份样式建立通用插件或额外设计系统包。
3. **最小必要重构**：将导航 active view 与内容面板解耦，将现有命令按全局/视口/节点操作分组，将 Inspector 按上下文分组。提取只用于完成对应用户切片，保持旧能力可用后再迁移，避免单独的大横向重写。
4. **面板与窗口**：默认从参考原型的 64px 导航、272px 左栏、320px 右栏出发，根据桌面可用空间约束调宽；1440×900、1920×1080 与 1100×800 为明确验收尺寸，不声明手机支持。调宽值必须与实际宽度一致；缩窄窗口时对面板宽度作约束或允许主动收起，保持展开入口可达。左右面板和抽屉内部滚动，画布随有效视口尺寸重算。
5. **导航与焦点**：窄导航切换场景/资源/项目；再次激活当前导航允许收放该面板。折叠后恢复已有页签及内容状态。拖动、键盘调宽、收放和菜单关闭后焦点有稳定归属，不截获文本/数值输入中的快捷键。运行时和 editor 不因面板或 locale 切换而重建。
6. **工具分组**：项目打开、完整/部分导出和语言入口进入全局菜单；撤销/重做、选择/变换维持直接可用；聚焦、相机、辅助显示和节点操作按关联放入工具组或明确更多菜单。迁移后每个现有操作都可达，能力不足的操作继续使用 Core capability 判断和禁用原因。
7. **场景层级**：消费现有 Workbench hierarchy 和 selection contract，涵盖对象、分组、灯光、相机及 imported target；不得因示例整体模型的简化而隐藏正式 imported target。不可独立变换的共享目标仍显示已有诊断。
8. **属性归属**：对象属性组显示当前节点摘要、适用的变换/材质以及被选灯光/相机的适用字段；环境组显示环境照明与背景；场景组提供场景范围灯光及相机视图管理。两处入口指向同一 Core 数据，不各存一份编辑值。空选择保留环境/场景访问；material-slot 自动定位和回 owner 的 object override 语义保持不变。
9. **深层表单**：将现有材质、环境、灯光和相机表单统一为同一视觉语言，保留全部现有字段、预设、验证反馈和操作。向量字段按 XYZ 并排显示；角度展示/转换遵循现有字段 contract，输入草稿在 commit 前不改变 durable state。
10. **资源与恢复**：保留导入队列、raster intent、搜索过滤排序、引用/载荷状态、替换、missing recovery 与 GLB reimport/remap 反馈。多文件部分失败逐项呈现；异步结果不得覆盖较新的选择或替换操作结果。
11. **项目与问题**：保留完整及部分导出语义、项目 readiness 与 warning/error 反馈。状态栏只显示摘要，详细分组与恢复入口集中在问题抽屉/项目内容；关闭详情不清除问题。正式界面不包含“演示问题”开关或固定成功状态。
12. **状态边界**：继续使用现有 Core command/history/runtime。默认无 schema 变更。Three.js 对象、File、Blob、object URL、加载资源、PMREM、resolver 输出及 UI/session 状态均不进入 Scene Snapshot。持久化模型、环境引用和展示意图依照现有 Scene Snapshot 与项目包资源契约表达。
13. **展示示例**：默认模型、镜头与照明只由 React/Vue demo 宿主初始化；新建空 editor 和自定义 snapshot 不自动获得样例对象。模型不要求是无人机或固定头盔；使用可分发且有来源记录的资源。参考模型的授权说明需纳入资产选择；若不适合正式分发，使用明确许可的替代模型，保持同等级构图与材质呈现。
14. **示例可恢复性**：正式默认展示场景的关键照明与默认镜头必须能通过既有 asset/environment/presentation contract 与项目包表达，打开导出包后视觉应等价。原型 renderer 的 RoomEnvironment 临时兜底不能成为不可导出、不可编辑的隐藏产品依赖。PMREM 本身仍只在 runtime 派生。
15. **公开接口**：保留 React render props / Vue scoped slots 的 toolbar、leftPanel、兼容 sidePanel、viewportOverlay、rightPanel、status 区域和既有优先级；showDefaultToolbar 只控制默认工具，不能吞掉宿主自定义 toolbar。自定义区按既有职责放置，不强迫其承受默认浮动按钮的尺寸。上下文保持 editor/snapshot/dispatch 等现有含义。
16. **双语与兼容**：保留 en/zh-CN、受控/非受控 locale、宿主 translate、切换器可见性/禁用与 Vue update:locale。新增 UI 文案纳入相应字典。React useEditor 当前返回 editor，Vue 返回对象，两者不因改版而强行统一；只处理有证据的类型接入问题。
17. **迁移顺序**：React 完整编辑能力和视觉验收完成后再启动 Vue UI 迁移。正式实现从主代码基线演进；原型作为视觉和交互依据保留，不整分支合并模拟数据、内部深层导入或原型开关。

## Testing Decisions

已确认的测试边界：以现有“挂载真实宿主工作台并操作可见控件”的浏览器边界作为唯一跨框架端到端入口；以适配器 Workbench/Inspector 的 DOM 行为和 package-root 类型用例补充，不新增 UI 改版专用 Core 抽象或重复核心算法测试。

1. **外部行为优先**：测试用户输入、可见状态、可访问名称、编辑结果和项目恢复；不锁定内部 hook、私有状态、DOM 子节点数量或每一条 CSS 声明。
2. **端到端闭环**：覆盖导入真实 GLB→树/画布选择→字段与坐标轴变换→撤销/重做→材质目标→保存/打开→验证等价选择、变换、材质、环境、场景灯光与默认相机及实际展示画面。示例加载路径与空宿主导入路径分别验证。
3. **DOM 和公开接口**：对菜单、分组、导航、状态抽屉、恢复动作、受控 locale、render props/scoped slots 与空/禁用/错误状态采用现有 React/Vue Workbench 和 Inspector 测试模式；package-root 编译用例确认集成不破坏。
4. **桌面布局**：在上述三个桌面尺寸检查页面不溢出、状态栏/工具可达、右栏内部滚动；实际执行鼠标与键盘调宽、两侧收放和抽屉展开，确认 canvas resize 及指针定位仍正确。
5. **视觉验证**：固定场景、相机、光照与窗口尺寸，对照 reference 原型截图检查主区域、色彩、边距和密度。截图配合人工审阅，不能仅凭非空 canvas 或 DOM 断言宣称视觉已达标。
6. **双语与扩展**：两框架在 en/zh-CN 下跑关键闭环；新增状态/错误文案不得以英文回退掩盖缺失翻译。切 locale 或导航后保留选择、history、editor/runtime 实例。验证自定义区域覆盖与 sidePanel 兼容优先级。
7. **Core 边界**：没有 Core 行为变化就复用已有核心测试。若出现真实 command/schema/runtime 缺口，先记录与本规格的差异，再在既有最高合适边界补回归；不能把宽度和页签塞进 durable state 来绕过 UI 状态设计。
8. **回归基线**：原型验证 24 项通过、构建通过；此前全量单测 882/883 后工作台 45/45 单独复跑通过，存在并发超时风险。浏览器旧中文断言期待“选择 none”而当前为“选择 无”，在主代码基线复现。先修正有证据的断言/类型基线，保留真实行为检查，不用跳过测试使之变绿。
9. **命令**：各切片运行对应适配器行为/类型/浏览器验证；最终运行 pnpm build、pnpm typecheck、pnpm test、pnpm test:browser 及两个示例 build。若保留既有手机回归，可继续运行，但本规格不新增手机 UI 功能。

## Out of Scope

手机布局；动画时间轴和关键帧；新物理系统；新的材质图或 imported-target remap 算法；云项目、模型市场、协作；跨会话持久化布局；新的插件框架；通用主题/暗色模式系统；新增语言；强行统一 React/Vue hook 返回形状；升级核心 durable schema；直接发布 npm 或合并原型。
