# HTTP 数据源管理首期实现规格

Status: ready-for-agent

日期：2026-10-26。用户已认可“连接 → 查询 → 字段映射 → 对象绑定”的原型流程，并要求整理正式规格和分阶段任务。当前授权限于规划文档；任务就绪不代表已授权执行实现。

流程基线为独立分支 `codex/http-data-source-prototype`、提交 `d719828` 中的[原型](../http-data-source-prototype/index.html)与[说明](../http-data-source-prototype/README.md)。前置材料为[需求草案](requirements-draft.md)及[实践调研](../../docs/research/2026-10-25-http-data-source-best-practices.md)。本规格是实现和验收的主依据；原型中的模拟实现不直接进入正式包。

## Problem Statement

场景编辑者目前可以导入、组织、变换和保存 3D 对象，但无法统一配置业务接口、解释响应字段、复用设备数据或为对象配置实时展示。直接在每个模型中填写 URL 和 JSON 路径，会重复认证与请求，并使接口调整、异常反馈和项目恢复难以维护。

首期需要把已有 HTTP JSON 服务转换为稳定的设备属性，使同一查询可被多个对象复用；配置可保存和撤销，实时数据不污染场景快照，网络或字段失败时仍能解释和修复。

## Solution

左侧新增数据工作区，按连接管理查询；宽配置窗口承载请求、映射和结果预览。选中 GLB object node 后，在对象 Inspector 中配置一个查询上下文、设备 ID、详情字段与一组颜色规则。工具栏启动或停止数据预览，点击对象显示屏幕详情卡。

首期正式支持多个连接、多个查询与多个对象绑定；原型的一个连接、一个查询、两台水泵只是演示数据量。每个对象仍限定一个查询上下文，不引入设备管理系统、跨查询合并或外部控制。

## User Stories

1. 作为场景编辑者，我希望创建并复用服务连接，以便统一管理地址和认证引用。
2. 作为场景编辑者，我希望搜索、编辑、复制和删除未使用的连接，以便维护多个业务服务。
3. 作为场景编辑者，我希望在连接下创建多个命名查询，以便分别使用不同接口。
4. 作为场景编辑者，我希望查看最终请求摘要与响应，以便确认接口参数和失败原因。
5. 作为场景编辑者，我希望定义带类型的参数并分别管理默认值、测试覆盖值和绑定覆盖值，以便测试不改变正式配置。
6. 作为场景编辑者，我希望手动执行 GET 和明确只读的 POST，以便接入现有读取接口。
7. 作为场景编辑者，我希望在没有网络时粘贴示例 JSON，以便继续配置映射。
8. 作为场景编辑者，我希望选择单设备对象或设备数组的数据位置，以便兼容已有响应包装。
9. 作为场景编辑者，我希望明确设备 ID 与显示名称，以便模型改名不影响业务身份。
10. 作为场景编辑者，我希望定义稳定属性键、类型、单位和简单转换，以便不同接口输出一致的业务属性。
11. 作为场景编辑者，我希望对照原值、转换后值和校验结果，以便发现字段、类型与重复 ID 问题。
12. 作为场景编辑者，我希望区分采样时间、接收时间与源质量，以便理解数值是否可作为当前状态使用。
13. 作为场景编辑者，我希望为单个 3D 对象选择查询、参数和设备，以便关联对应业务设备。
14. 作为场景编辑者，我希望选择详情字段、顺序和数字显示精度，以便点击对象查看有用信息。
15. 作为场景编辑者，我希望按一个属性配置有顺序的颜色规则，以便快速识别运行状态或温度区间。
16. 作为场景编辑者，我希望先试用当前对象的草稿效果，以便在保存前检查配置。
17. 作为场景编辑者，我希望显式启动与停止数据预览，以便控制何时取数和展示实时外观。
18. 作为场景编辑者，我希望相同查询和参数的多个对象共用请求，以便减少重复访问。
19. 作为场景编辑者，我希望配置刷新间隔与过期阈值，以便按接口时效显示最新状态。
20. 作为场景编辑者，我希望错误或过期时有明确诊断并恢复原始外观，以便不误认旧数据为当前正常状态。
21. 作为场景编辑者，我希望一台设备的坏字段不影响其他有效字段或设备，以便保留可用展示。
22. 作为场景编辑者，我希望停用、解除和修改绑定，并通过撤销/重做恢复配置，以便安全调整场景。
23. 作为场景编辑者，我希望查看连接、查询和属性的使用位置，以便在删除或不兼容修改前处理引用。
24. 作为场景编辑者，我希望复制、删除、移动或重新导入对象时保留正确的绑定语义，以便维护模型而不误绑设备。
25. 作为项目使用者，我希望导出并恢复数据配置，以便在 React、Vue 和 vanilla host 间继续编辑。
26. 作为项目使用者，我希望缺少凭证或执行器时仍能恢复和编辑配置，以便重新连接业务环境。
27. 作为宿主开发者，我希望注入请求执行与凭证描述能力，以便控制浏览器直连或服务端网关访问。
28. 作为宿主开发者，我希望在无 DOM/WebGL 的情况下配置、测试和订阅数据，以便复用框架无关契约。
29. 作为 React/Vue 使用者，我希望两套 UI 的字段、默认值、保存、异常和生命周期一致，以便选择框架时不改变业务语义。
30. 作为双语与键盘使用者，我希望语言切换、焦点和输入操作可靠，以便连续完成配置而不丢草稿或重建 runtime。
31. 作为维护者，我希望停止、替换配置和销毁后不会残留请求、计时器或材质覆盖，以便重复挂载仍可预测。
32. 作为包使用者，我希望默认空 editor 保持为空且不自动联网，以便由宿主明确决定展示内容与网络行为。

## Implementation Decisions

### D01 职责与交付边界

| 责任 | core | React | Vue | 宿主 |
| --- | --- | --- | --- | --- |
| durable 配置 | 版本、类型、默认值、校验、引用、command/history | 收集草稿，调用 command | 同左，Vue 原生实现 | 可传入合法 Snapshot |
| 请求与结果 | 请求构建、参数解析、超时/取消、成功判定、映射、运行态订阅与调度 | 呈现执行结果 | 同左 | 执行实际 HTTP、提供凭证与网络策略 |
| UI 模型 | 数据工作区、绑定 Inspector、能力、问题及文案描述符 | 组件、表单草稿、焦点、布局、详情卡 DOM | 组件、composable/ref、slots、详情卡 DOM | 选择性自定义 UI |
| 颜色和预览语义 | 节点目标、规则求值、材质资源、覆盖与恢复、编辑能力限制 | 开关、反馈与选择意图 | 同左 | 使用公开 API |
| 生命周期 | 一个 editor 一个数据服务，独立于 viewport；统一停止与 dispose | 订阅/退订；只释放自有 editor | 同左；处理 editor ref 替换 | 管理外部 editor 所有权及凭证轮换 |
| 兼容与文档 | Snapshot/项目包/clipboard/公开导出 | React package-root 与集成文档 | Vue package-root 与集成文档 | 负责服务端鉴权、租户隔离、网络边界 |

不新建插件系统或独立后端产品；core 内部分开 durable contract、数据执行服务和 Three.js 投影。React/Vue 不实现 reducer、映射器、轮询器或直接操作材质。沿用仓库 Snapshot-first、稳定 NodeId、runtime projection、薄适配层和包内 UI 样式边界。

### D02 版本化配置

以当前 v8 为基线，首次引入数据域时升级到 Scene Snapshot v9，新增顶层 `dataSources`，其中包含连接 map、查询 map、以 object NodeId 为 key 的绑定 map。连接与查询各有稳定 ID；一个对象最多一份绑定，不额外创建易失的 Three.js 身份。若实施前基线已升级，按届时实际版本顺延，不能覆盖其他 schema 变更。

| 配置 | 持久化内容 |
| --- | --- |
| 连接 | 稳定 ID、名称、HTTP/HTTPS 服务地址及固定前缀、认证方式与凭证引用、非秘密公共头、默认超时 |
| 查询 | 稳定 ID、connectionId、名称、GET/只读 POST、相对路径、参数定义与默认值、头/查询参数/body 模板、可选业务成功条件、映射、更新策略 |
| 映射 | 单对象/数组模式、数据根路径、设备 ID 来源与显示名、属性定义、有限转换、可选时间与源质量映射 |
| 绑定 | object NodeId、queryId、参数覆盖、设备 ID、启用状态、详情字段/顺序/精度、一组颜色规则 |

旧版本迁移得到三个空 map，不合成演示连接或绑定。配置必须纯 JSON，引用闭合；恢复时缺少凭证、执行器或尚未加载模型是运行时可恢复问题，不是 Snapshot 损坏。未知查询 ID、目标 NodeId 不存在或目标类型不合法则是配置校验错误。

原始响应、标准样本、测试参数、测试成功标记、错误对象、凭证解析结果、预览开关、timer、Promise、AbortController、resolver 结果和 Three.js 资源均不进入 Snapshot、history、项目包或 clipboard。

### D03 命令与编辑事务

连接、查询的增改删/复制和对象绑定的设置/解除通过 command；保存一个窗口草稿产生一个可撤销编辑事务。连接先独立保存；查询与映射共同保存。表单输入、单次执行和每次轮询不产生编辑历史。

名称在连接级或同连接查询级去重；复制只复制所选配置并生成新 ID/名称。复制连接不复制其查询；复制查询不复制对象引用。被使用的查询或连接不能直接删除。被引用属性的键/类型及已使用参数的删除/类型改变须先解除或调整引用；兼容的显示名、单位和转换允许更新并重新校验。改地址、认证、路径、默认参数或映射会失效相关结果，不影响无关查询。

批量/嵌套命令同样遵守引用与类型校验；失败保持 Snapshot/history 原子不变。数据配置变化使用独立 revision；普通选择、镜头操作不导致数据重新请求。

### D04 数据服务与公开边界

editor 提供独立的数据服务门面：读取运行态、订阅/退订、执行一次已保存查询或合法查询草稿、取消、启动/停止全局预览、刷新、单对象试用/结束试用、替换宿主执行能力。配置编辑仍走 dispatcher，不另建第二份配置 store。

服务可在无 DOM/WebGL 环境创建和执行。未挂载 renderer 时数据订阅仍工作，视觉能力报告不可用；挂载后按当前有效样本投影。`editor.dispose()` 统一停止该服务；viewport 卸载释放投影资源但不擅自销毁宿主 editor。默认 editor 不带请求执行器，不自动联网。

现有 `createEditor`、Editor/EditorWithGlbImport、useEditor、useWorkbench 与公开 package-root 类型采用新增能力的方式扩展；旧调用保持可用。两种 adapter 的创建选项传递同一宿主能力，宿主传入 editor 时不重复创建数据服务。新增运行态订阅独立于 Snapshot 订阅，持续更新不能靠伪造场景编辑驱动界面。

### D05 宿主执行器与凭证

core 生成已解析的请求描述：method、最终地址、非秘密 headers、可选 JSON body、认证方式/credentialRef、timeout 和 AbortSignal。宿主执行器进行网络访问与秘密注入，返回受限的响应状态、允许的响应头、content type 和受大小限制的文本体；core 统一判定并解析 JSON，在实际接收时记录 receivedAt。执行器及返回值始终是运行态。

宿主另提供凭证描述列表（引用、名称、是否可用，不含秘密）与认证上下文 revision。凭证变更、注销或执行器替换必须更新 revision，取消并失效旧上下文；不同 editor 或认证上下文不共用结果。执行器不得将秘密写回请求摘要、错误 metadata 或日志。浏览器会话允许使用宿主明确授权的用户态凭证；需要保密的服务凭证由网关持有。

UI 只选择已有凭证，不提供把密钥保存进场景的输入框。真实服务端鉴权、来源/网络允许范围、重定向、速率和租户策略由宿主负责；首期不提供任意服务端代理。正式示例与浏览器验收需通过本机同源受控 HTTP 夹具演示真实请求，不能只以模拟执行器代替 HTTP 集成验证。

### D06 HTTP 请求与参数

支持 GET 与明确只读的 POST。首期 POST **仅手动执行**：测试、首次开启预览或显式刷新可触发，禁止计时轮询及自动重试；原型外草案中可选的自动 POST 不纳入本期。

请求路径相对服务前缀拼接；拒绝绝对 URL、协议相对 URL、userinfo 和穿越前缀的路径，不使用用户输入替换连接主机。路径参数编码后插入；query 参数使用标准编码。body 参数为结构化的整值引用，保留 number/boolean 类型，不执行字符串表达式或脚本。认证保留头不可被公共/查询头覆盖。

参数类型为 string、finite number、boolean；区分未提供、空字符串、0、false。有效参数为默认值加显式覆盖；测试与绑定覆盖隔离。缺少必填值或类型错误时不调用执行器。可选业务成功条件为一个字段路径与一个 JSON 标量严格相等；HTTP 失败、业务失败、非 JSON 和解析失败分别返回诊断。204 及有效空结果是本次无数据。

默认 timeout 10 秒、GET 轮询间隔 5 秒、最大年龄 15 秒。时间配置必须为正，轮询间隔至少 1 秒，轮询下最大年龄不得小于间隔；内部统一单位并在 UI 以秒显示。响应超过宿主配置的硬限额时整次失败，不能静默截断成完整设备集合。

### D07 映射与标准数据

路径持久化为对象键/非负数组索引的有类型片段，UI 可显示易读路径。禁止通配、递归查询、脚本及原型链访问。数组模式每行一个设备；单对象模式允许设备 ID 来自字段、明确的参数或固定值。字符串 ID 保留原样；数字 ID 需显式有限数值到字符串转换，空 ID 行无效；同一结果重复 ID 使整次结构映射失败。

属性键在查询内唯一，定义显示名、number/string/boolean、可空性、单位、可选范围/枚举。转换限定为原值、显式严格数值转换、数值乘系数加偏移、有限布尔/枚举对应表；不使用 JS 的宽松真假或空值转数值规则。单位仅作显示元数据，换算必须显式配置。

结果按完整集合替换，不作增量累积；本次消失的设备/属性立即不可用。缺失、null、转换失败、范围失败分别诊断；单属性错误隔离，设备 ID 冲突或根结构错误整体失败。可空 null 仍表示无可展示值，不触发视觉规则。

标准样本带来源 connectionId、queryId、执行上下文身份、entityId、propertyKey、值、observedAt、receivedAt 和 sourceQuality；属性定义来自保存的查询。不同查询结果保持独立，同名字段不互相覆盖。时间可配置含明确时区的 ISO、Unix 秒/毫秒并统一为 UTC；未提供为未知，已配置但无效/缺失时报告时间问题，不伪造接收时间为采样时间。quality 映射到 good/uncertain/bad/unknown，未提供为 unknown；HTTP 成功不推断设备测量质量。

### D08 调度、缓存隔离与失效

全局预览默认关闭。开启时仅运行启用绑定需要的有效查询上下文；手动查询执行一次，GET 轮询在前次完成后调度下一次。一次性测试、样本预览与正式上下文隔离，即使参数相同也不能把示例结果冒充实时值。

上下文共享键包含 queryId、规范化后的有效参数、连接/查询配置 revision 和宿主认证 revision；对象 ID、设备 ID不参与列表查询共享键。单设备路径中的 deviceId 是参数，因此不同 deviceId 不共享。键不含秘密；只在单 editor 数据服务内共享，无订阅者后停止并清理。首期每 editor 最多 4 个同时在途上下文，其余去重排队；此数值限制资源使用，不构成吞吐承诺。

同上下文不重叠/不堆积请求。取消、停用、配置更改、undo/redo、恢复、executor 替换和 dispose 使相关 generation 失效；即使执行器忽略 abort，晚到响应也不得提交。刷新运行中的上下文不新增平行请求。

GET 的网络失败、超时、408、429 和 5xx 使用以轮询间隔为基数、指数增加且不超过 60 秒的退避；若有合法 Retry-After，以较晚的允许时间为准。成功后重置退避。401/403 暂停直到认证 revision 改变或用户修复后重试；其余 4xx、解析/业务/结构错误停止自动执行并等待修复或显式重试。手动 GET/POST 不因失败自动执行。

刷新中仍有效的当前值可以继续展示；失败结果、空集合和缺字段立即使受影响颜色回退。新鲜度按接收年龄及可用源采样年龄分别计算，超过任一阈值即过期；无后续响应也必须按时过期。源时间晚于 receivedAt 超过 30 秒时标记时间无效，不据此延长数据寿命；此容差处理小幅时钟偏差，不代表允许未来测量。时间无效时显示数值及明确问题，停止对应设备的数据颜色。保留上次有效值时另标时间与历史身份，不继续当作当前有效值。

### D09 对象绑定、详情与交互

首期仅 GLB object node 整对象支持绑定。多选、group/light/camera/imported node 说明不可用原因，并允许显式选择 owner object；不静默转移目标。一个对象绑定一个 queryId、有效参数和设备 ID，可选择多个详情字段和一组颜色规则。不存在于当前结果的设备允许保存为等待数据，非法配置引用不能保存。

详情字段可排序、改显示标签和数字精度；从属性定义取得默认标签/单位。卡片为屏幕 DOM，位置与开关是 UI 会话状态，内容与状态由 core model 提供。点击选择沿用已有 NodeId picking；预览时不自动跨设备查询，也不将点击结果写回业务服务。

颜色支持一个属性的有序规则；boolean/string 为等于/不等于，number 为比较或单区间，首条匹配生效，默认恢复 authored 颜色。无值、错误、过期、bad/uncertain 不应用数据颜色；unknown 质量可显示有效值并提示来源质量未提供。详情可以独立工作，颜色不支持不使整个绑定失败。

### D10 材质投影、试用与编辑限制

core 在 authored material projection 之后应用单独的 runtime 颜色覆盖，使用投影拥有的隔离资源；仅修改匹配对象的 MeshStandardMaterial 基础色，其他材质显式报告不支持，禁止篡改共享 loader 材质或其他对象。混合材质对象逐目标报告支持情况；支持部分可覆盖，不支持部分保留 authored 外观并汇总诊断。

覆盖必须在模型异步加载完成和场景重新投影后重新求值，不因选择或其他 Snapshot 更新丢失。停止、取消试用、停用、解除、失败、过期、模型替换和 dispose 正确移除覆盖并释放资源；恢复的是最新 authored 基线，包括已有材质槽配置，而非固定蓝色或旧缓存。纹理、灯光和色彩管理不变。

草稿“试用效果”在全局预览关闭时仅作用当前对象，以明确标记的示例/测试结果一次性展示；关闭、取消、切换目标或结束试用恢复基线，不启动轮询也不提交配置。全局预览保留选择、镜头导航及数据配置编辑，暂停场景变换/材质等作者操作；core 暴露能力并对绕过 UI 的受限编辑返回可控错误。undo/redo、restore/import 先停止预览再执行，以保持原有编辑语义。

### D11 引用、节点操作和项目包

重命名、移动、分组不改变绑定；object node 身份不变的 GLB 重导入保留绑定，模型未解析时保留配置并显示问题。删除节点/子树同时清理对应绑定，撤销一次恢复。duplicate 和同 editor copy/paste 为新 NodeId 复制配置，默认仍是原设备，明显显示该摘要。

节点 clipboard 以新增版本保存绑定及必要的连接/查询纯配置片段，并继续读取旧版本。跨 editor paste 若 ID/定义完全相同可复用；冲突时分配新连接/查询 ID、重写所有引用并去重名称，不覆盖目标 editor 现有资源。凭证引用只按逻辑引用搬移，目标宿主重新提供；不携带秘密、样本或 executor。旧 object-only clipboard 不被破坏。

Snapshot serialize/restore 和 `.ek3d` 保留四类配置；容器布局及项目 manifest v1 不因仅增加 scene 字段而升级。导出不携带实时样本/成功状态，缺网络/凭证不导致失败。恢复先取消旧上下文、移除颜色、关闭预览，等待显式重新连接；跨 React/Vue/vanilla 恢复结果等价。

### D12 工作台与适配器

React 先交付可用切片；Vue 在 React 完整流程基线之后实现相同工作区、宽配置窗口、Inspector、详情卡和问题定位。复用 core 的字段、能力、引用统计、状态、校验与文案描述符；React hook/render props 与 Vue composable/scoped slots 只适配生命周期与 UI。

配置窗口按连接、请求、映射、绑定组织步骤；请求结果可独立查看。连接保存和查询共同草稿的事务边界明确。创建查询后返回原对象绑定草稿；切页保留草稿，关闭未保存内容给出继续/放弃选择。所有 API 状态与输入焦点稳定，语言/面板切换不重建 editor 或 WebGL runtime。凭证缺失、离线或未测试时允许保存合法配置。

布局遵守已有包内 styles 发布与弹层主题边界；复用现有控件，不照搬原型的固定页面尺寸。新增工作区、表单、状态、错误和无障碍标签均提供 en/zh-CN；无需宿主生成 Tailwind 样式。宿主自定义 render regions/slots 和旧 props 保持可用。

### D13 问题与可观测状态

扩展结构化 Problem target 定位连接、查询、绑定对象及字段；数据服务问题不依赖 WebGL runtime 挂载。command/配置错误同步返回；连接、执行、映射、时间和目标问题为派生诊断。工作台汇总 data/runtime/project 问题，不把其中任一反写 authored problem state。

请求阶段、当前字段有效性、新鲜度与源质量是独立维度，不压成唯一枚举。相同位置的持续故障稳定更新，修复后清除，不按每次轮询累加。摘要可显示最近执行、共享上下文、绑定引用和更新时间；原始响应仅当前会话可查看，默认不输出到日志或项目文件。

## Testing Decisions

主验收边界采用既有 React/Vue proof-loop 宿主的用户操作：配置服务、执行真实同源夹具请求、映射、绑定真实 GLB/WebGL 对象、轮询/异常、停止、保存/恢复。优先复用既有 Editor、dispatcher、serialize/restore、runtime 和 package-root 接口，不为测试再建一套生产 API。

| 层级 | 需要证明 | 测试方式 |
| --- | --- | --- |
| core 公共行为 | v9/旧版本迁移、命令原子性、参数/映射、共享上下文、取消/晚到、过期/重试、dispose、clipboard 与项目往返 | 通过公开 Editor/数据服务，注入可控 executor/时钟；只断言输出、调用次数和可见状态，不锁私有类结构 |
| Three.js runtime | 两对象共享资产仍隔离材质、有效/错误/过期/停止恢复、异步加载与重新投影、资源清理 | 现有 runtime 集成边界加必要浏览器 WebGL 行为；结构断言为主，不做脆弱像素快照 |
| adapter 行为 | 草稿与提交、焦点、参数隔离、订阅/退订、宿主 editor 所有权、en/zh-CN、render prop/slot 兼容 | 现有 Workbench/hook/composable DOM 用例；不在两框架重复测试 core 算法 |
| 跨框架交付 | React 导出 → Vue 恢复 → vanilla 查询；相同业务状态/问题；默认空宿主零请求 | 同一受控 HTTP/GLB 夹具和真实项目包；验证真实请求与用户行为 |

每个任务完成与其变更相关的验证；涉及 viewport/runtime 时包含 `pnpm test:browser` 的相应范围。收尾执行 `pnpm build`、`pnpm typecheck`、`pnpm test`、`pnpm test:browser`，以及现有发布验证；不因本任务自动发布包。浏览器全套配置中的旧小尺寸实例不得被移除；新工作流在 1440×900、1920×1080、1100×800 做桌面布局验收，窄宽度仍能关闭窗口/定位问题，不承诺移动编辑器。

## Out of Scope

设备控制与外部写入、自动 POST、OAuth 管理后台、后端网关产品、团队权限、跨场景数据源库、分页自动取全量、MQTT/WebSocket/SSE、历史时序和回放、任意脚本/表达式、OpenAPI 导入、跨查询拼接、全量设备管理、3D 文本与自由布局标签、动画/变换/可见性绑定、模型内部节点或材质槽数据绑定、批量对象绑定编辑，以及将模拟 SVG 场景推广为正式 viewport。

## Further Notes

1. 流程认可来自本次用户请求；技术默认值用于形成可执行规格，不冒称用户逐项选择了全部内部 API。命名可随实现保持仓库风格，职责与外部语义不变。
2. 性能验收先采用受控 100 个对象、单一列表查询、100 台设备×2 属性、5 秒轮询与连续 3 周期，验证共享、无队列积累和可交互性；不据此宣传生产吞吐。更多规模另立性能目标。
3. 多数原型简化不构成正式限制：正式支持多连接/查询、真实执行器、独立单次测试、规则和字段选择、项目往返与资源生命周期；固定 code=0、示意 SVG、刷新清空配置等不作为正式行为。
4. 不改变现有 ADR；React 包内组件与样式自包含、Vue 原生对齐的边界继续适用。新增领域仅在此规格中定义，不提前修改当前能力文档以伪装已实现。
5. 依赖、责任、范围和验收以[阶段任务索引](README.md)和每张任务为准；当前没有实现任务被启动。
