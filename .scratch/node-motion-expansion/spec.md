# 场景动效扩展规格

Status: ready-for-agent

确认日期 2026-11-27

## 问题

编辑者已经可以在「对象 → 动效」给单个节点配置持续自转或往返移动，并在编辑器中预览。设备展示还需要能在重新打开项目后播放这些动作、响应点击和设备数据，并表达部件、材质、路径以及相机的变化。

## 方案

编辑者在现有工作台配置和预览动效，在同一宿主的「展示模式」浏览场景并触发已保存的动作。首个可独立交付的功能是「点击开门」。在面板设置轴向、90°、时长和缓动，停止编辑预览后门恢复原姿态。将项目保存为 .ek3d 后重新打开并进入展示模式，点击门，门转到 90° 后保持打开。

后续为设备动作和状态增加多动效、数据触发及实时映射，再交付路径、资源自带动画、部件展开、视觉特效和相机切换。时间轴可编排这些动作，也可用关键帧直接编辑多对象的属性。

## 用户故事

1. 作为编辑者，我希望在现有「动效」面板设置轴向、角度、时长和缓动，以便制作定角启闭。
2. 作为编辑者，我希望沿轴配置一次性位移、时长和终点表现，以便演示滑台或气缸伸出。
3. 作为编辑者，我希望继续配置和预览持续自转与往返移动，以便复用已有设备场景。
4. 作为编辑者，我希望设置单次、循环或往返播放，以及适用的延迟和结束行为，以便表达不同的工作节奏。
5. 作为编辑者，我希望在同一节点上添加、修改和删除多条动效，以便分别设定该节点的机械动作与状态表现。
6. 作为编辑者，我希望停止或退出编辑预览后恢复编辑状态，以便继续调整节点。
7. 作为编辑者，我希望撤销、重做、保存和恢复动效配置，以便反复调整并把项目交给其他宿主。
8. 作为展示用户，我希望切换到展示模式并点击场景对象，以便看到配置好的动作。
9. 作为展示用户，我希望门开到一半时能从当前角度回转，以便开门和关门的操作可以接续。
10. 作为编辑者，我希望通过场景加载和点击指定对象触发动作，以便让设备自动开始演示，或让场景中的按钮控制另一节点。
11. 作为编辑者，我希望用设备字段和阈值触发动作，以便温度超限时启动告警。
12. 作为编辑者，我希望把实时读数映射到角度、位置或路径进度，以便按设备的实际状态展示阀门开度或车辆位置。
13. 作为展示用户，我希望风扇能在自转时同时改变颜色，以便同时看到运转与告警状态。
14. 作为编辑者，我希望设置缩放原点、幅度、时长和缓动，以便制作弹入和周期性缩放提示。
15. 作为编辑者，我希望设置颜色、高亮和不透明度的变化，以便指明设备异常或淡出外壳查看内部。
16. 作为编辑者，我希望画出或配置路径点、时长或速度、起止进度和转向规则，以便控制 AGV 的运动。
17. 作为编辑者，我希望让节点跟随或朝向另一个目标，并设置适用的轴向、偏移和阻尼，以便标记随设备移动或让检测头朝向目标。
18. 作为编辑者，我希望选择 GLB 自带动画片段，设置倍速、循环方式、循环次数和末帧行为，以便播放叉车升降等预制动作。
19. 作为编辑者，我希望指定展开的部件、偏移方向和距离、时长及部件间隔，并能触发复原，以便解释设备装配关系。
20. 作为编辑者，我希望设置扫光轴向、方向、颜色、光带长度和速度，以便让扫描光带在设备表面移动。
21. 作为编辑者，我希望设置流向指示的形态、方向、颜色和速度，并可用设备数据更新显示值，以便表现管道流向或传送带运行。
22. 作为编辑者，我希望设置粒子的发射范围、数量、寿命、速度和方向，并能启动或停止发射，以便表现蒸汽、水滴和烟雾。
23. 作为编辑者，我希望切换已保存的相机视角并设置转场时长和缓动，以便把用户带到下一处设备。
24. 作为编辑者，我希望在一条时间轴里安排多对象的动效、GLB 片段和相机切换，以便讲述完整的工序。
25. 作为编辑者，我希望为位置、旋转、缩放、颜色和透明度设定关键帧，以便控制指定时刻的场景表现。
26. 作为编辑者，我希望拖动播放头观察任意时刻的效果，以便检查多个对象动作的衔接。
27. 作为项目使用者，我希望已有项目继续打开和预览，并能在 React 与 Vue 宿主间交换新项目，以便升级时延续现有工作流。
28. 作为编辑者，我希望能在对应对象看到暂时缺失的模型、部件或数据字段，以便定位并恢复动效。

## 实现决定

- **配置与播放。** 延续现有场景节点、Core 命令、历史记录和版本化 Snapshot。动效配置及其引用、触发、实时映射、时间轴可以保存。当前帧、播放进度、临时变换和资源实例留在运行态。编辑预览结束后恢复编辑状态，展示端按配置保持末帧或复位。
- **宿主入口。** 现有示例增加可切换的展示模式，与编辑模式使用同一份项目。展示模式接收视口点击并定位场景节点，编辑控件在编辑模式可用。React 与 Vue 提供等价的配置、预览和展示行为，共享 Core 的播放语义。
- **兼容已有动效。** 打开旧项目时保留持续自转和往返移动的原有参数、轴向、周期以及预览和复位行为。支持在同一节点为多条动效单独保存配置。
- **属性控制。** 同一节点的不同属性可以并行。对同一属性，实时映射拥有控制权。演示动作在收到该属性的新触发时，从当前值接续。时间轴上的动作和模型片段遵循同一条属性控制规则。
- **触发。** 触发条件包含场景加载、点击指定场景节点、设备数据条件。触发节点可和动作目标相同，也可独立配置。实时映射连接已有设备字段和目标属性，读数更新时直接解析为目标值。设备结果与缺失数据状态沿用现有数据服务。
- **参数化效果。** 定角、单程位移、缩放、颜色和透明度共享适用的持续时间、缓动和播放方式。扫光、流向指示、粒子以及路径保留与自身效果相关的参数。可独立解析的 GLB 子节点可作为动效目标。
- **资源和场景动作。** GLB 动画从资产已有片段选择，配置保存可恢复的目标及片段引用。部件展开使用可定位的零件组，复原时回到该动作的基础状态。相机切换使用场景内已保存的相机视角。
- **时间轴。** 时间轴存储多个目标的时间位置、属性关键帧和已配置的动作。拖动播放头可以预览指定时刻。播放型动作、模型片段和相机切换可按时间编排。单个动作和时间轴共享播放与属性控制语义。
- **诊断。** 资源或引用暂时不可用时保留已保存的配置，通过现有问题入口说明对应节点、片段、路径或字段。缺失项恢复后可重新预览或播放。

## 验收与测试

- 首个验收使用实际工作台和展示模式。配置门的 90° 动作后预览、停止、保存并重新打开项目，在视口点击门并验证末帧保持。操作前后保存的基础姿态一致，显示姿态随播放变化。
- 在 Core 的公共编辑命令、项目往返和 runtime 播放入口验证配置持久化、旧项目恢复、退出预览、多个属性并行、同属性动作接续和实时映射控制权。沿用现有节点动效测试的行为边界。
- 对 React/Vue 的面板和浏览器视口做等价验收，覆盖节点选择、点击触发、显示状态和干净退出展示。跨框架证据沿用已有的项目恢复流程，用一端保存的项目在另一端重开并播放。
- 后续用真实设备数据夹具验证阈值触发与连续读数映射，用可独立选择的 GLB 部件验证路径、片段和展开。用「切镜头 → 开门 → 传送带运行」验证时间轴顺序及任意时刻的预览结果。
- 各交付任务验收其正常用户操作及对应项目恢复行为。浏览器验证覆盖本轮触及的视口及渲染入口。

## 交付边界

编辑入口是现有 React/Vue 工作台。展示端以现有宿主可集成的播放能力和示例内的展示模式交付。项目交换通过 .ek3d 完成。设备数据联动用于展示真实读数和触发场景中的动作。
